# Changelog

## v2.2.0 — 2026-10-04

### Fixed
- **User messages swallowed by the pending-compact input gate could be lost** — `onInput` tells the user the message "will run after the pending compaction", but delivery was fire-and-forget (`void pi.sendUserMessage`) from a timer closure, and the stash was emptied before the send. A send pi refuses (`prompt()` throws while its compaction-in-progress flag is still set) lost the message with no retry, and a second `session_compact` inside the 200 ms delay cancelled the timer and dropped its payload. The owed payload is now module-owned instead of captured by the timer closure, so a second compact folds it into the next redelivery and a re-scheduled redelivery appends rather than overwrites. A send pi refuses cannot be detected from the extension API at all: `ExtensionAPI.sendUserMessage` is typed `Promise<void>` (extensions/types.ts:400) while the runtime bridge returns `void` and swallows the rejection into `runner.emitError` (agent-session.ts:2469) — the handler type is `=> void` (types.ts:1585). Writing `.catch()` on it would throw a TypeError, and no retry can be conditioned on a signal that does not exist; pi's extension-error event is the only record.
- **A failed `compact_request` was presented as a completed compaction** — the `context` handler rewrote *any* `compact_request` toolResult paired with a call still in context into the completion marker, pi's thrown-error rendering included. In the field a params-validation rejection read as "Compaction complete" while the summary at the top of context was still an older one, so the model never learned the compact had not run. Two gates now decide it: the result must be the tool's own `Compacting.` (not `isError`), and the newest `compactionSummary` must not predate the exchange — an aborted compact, or a checkpoint re-used verbatim from an older entry, leaves the exchange intact so a re-request stays the correct recovery.
- **A failed compact left the compact latches and the pressure nudge spent** — `compactionInFlight` re-armed only at the next user message, so a later `compact_request` in the same run hit the re-entrancy guard and no-oped silently: the tool had already answered "Compacting." and nothing ran. `contextNudgeState` stayed `nudged` for the rest of the session (`reset()` runs on session_start / a *successful* compact only). Both re-arm on failure now (`onError`, `session_compact_failed`).
- **Gallop's own output shaping hid real failures from loop detection** — gallop's blocks were recognized by the result text starting with `[gallop]`, but binary suppression and repetitive-output collapse put that prefix on genuine failures (and a failing grep over gallop's own source ends with it). Such a failure was treated as "gallop already handled it": `lastFailedToolCall` cleared and the repetitive streak unwound. Blocks are identified by tool call id now (`noteBlockedCall`, recorded by the composition root at `tool_call`).
- **`compact_request` failing validation on a stringified boolean** — `continue` and `nuke` were declared `type: "boolean"`, and pi's argument validator only coerces the exact lowercase `"true"`/`"false"` (`packages/ai/src/utils/validation.ts`), so a harness that sends `"True"` killed the call before the handler ever ran. Both flags are now `boolean | string` and normalized by `boolFlag()` (`true/false/1/0/yes/no`, any case; unparseable → that flag's default). This also removes a silent inversion the old permissive parse allowed: `params.continue !== false` reads the string `"False"` as *continue*.
- **README contradicting the `continue` default** — the bullet said "Omitted/`false` = the agent stops"; the code and its tests default an omitted flag to *continue* (only `false` stops).
- **compact_request degrading to pi's native one-shot on a too-short summary** — when the model called the tool with a sub-200-char summary, the stash silently dropped it and `session_before_compact` returned `undefined`, so pi's cold one-shot summarizer ran — exactly what self-compact exists to avoid (a cold prefill of the flattened conversation; in field sessions it surfaced as a slow, low-quality compact after the model had already ended its turn). The minimum-summary check now lives in the tool's `execute`, where it fails the call (same pattern as the minimum-context guard): the error names the length and the minimum and tells the model to rewrite the full checkpoint and re-call; the run stays alive and no pending compact state exists. The native one-shot remains only for compactions no tool call preceded — user `/compact`, the automatic threshold backstop, overflow recovery.
- **Messages typed while a self-compact was pending ran on the stale context** — `compact_request` defers the actual compact to `agent_settled`, but a message typed in that window (Enter → steering queue, Alt+Enter → follow-up) is processed by pi's post-run loop *before* the agent settles — the user's turn ran on the un-compacted context and the compact was delayed until that run ended (field: the compact only fired when the run was aborted). The input handler now swallows interactive messages while `pendingCompact` is set (`{ action: "handled" }`, with a "message saved" notify); `session_compact` re-delivers them after the compaction (200 ms — `session_compact` fires while pi's compaction-in-progress flag is still set and `prompt()` refuses to submit during compaction), in order, via `sendUserMessage` (followUp when a run is active, direct when idle). The stashed messages *are* the continuation, so the generic proceed steer is skipped — including the manual path's `onComplete` (suppressed via `stashedRedeliveryPending`). `session_compact_failed` delivers the stash immediately so failed compacts never drop user input; `resetAllState` discards the stash and any pending redelivery timer (a new session keeps none of it). Extension-source input (gallop's own steers/nudges) is never swallowed; once a compact is actually running, the TUI routes typed messages through its own compaction queue and they never reach the gate.
- **Stale pressure nudge right after a model-initiated compact** — pi emits `message_end` *before* a message's tool calls execute, so when the model's final message *was* the `compact_request` call, the nudge's en-route guards (`pendingCompact`, `compactionRunning`) saw nothing — the tool's `execute` had not run yet. The nudge steer was queued around the compaction boundary and reached the context as "call compact_request now" immediately after the model had just called the tool (rendered between the user's compact command and the completion marker — a live instruction that read as stale). `checkContextNudge` now also skips messages that contain a `compact_request` tool call: the compact is already en route and the call terminates the run, so a nudge can only be noise. The suite now exercises the real pi order (message_end before execute) — the pre-existing pending-compact test ran the tool first, the reverse order, which is how this slipped through.
- **Double compact after a `continue: false` self-compact** — the context handler's exchange pruning removed the model's compact call *and* its result while the pressure nudge that triggered it ("…call compact_request now") stayed in the kept tail — an instruction with no visible fulfillment (and `continue: false` delivers no other completion signal; the nudge even renders *after* the compaction summary, so it looks freshly issued). The resumed model re-requested compaction; a field session showed two back-to-back double-compacts, the second preempting the user's "proceed to phase 2". The exchange is now replaced with a fixed in-context completion marker (`COMPACT_DONE_MARKER`: "Compaction complete — the summary at the top of context is your current state. Do not call compact_request again unless context pressure returns.") in assistant position: verbatim-carried call → the call message becomes the marker and the result drops; native-fallback (short/absent summary) → the call stays as a true record and only the in-progress "Compacting (…)" result text is rewritten; batched calls keep their siblings and get the marker appended as a text block; orphaned results still drop. No compaction summary in context (abort / pre-compact tree view) → nothing changes, so a re-request after an aborted compact remains the correct recovery. The triggering nudge is left untouched (a live post-compaction nudge is indistinguishable from a stale one in the rendered context) — with the marker present it reads as fulfilled. Documented edge: an aborted *botched* compact with an older compaction in context is marked done; a missed re-request then waits for the next pressure point (pi's overflow recovery backstops).

### Added
- **Post-compaction evidence package** — after each self-compaction, two invisible deterministic blocks land in context (custom messages, `display: false`, `triggerTurn: false`, scheduled 200 ms from `session_compact` so they are in context before the continue steer / stashed redelivery starts the next turn): (1) a **protected user-message block** — the covered user messages verbatim (synthetic `[Gallop]`/`[Memory]` messages and the `[Memory]` recall-hint suffix stripped, newest-first within a 16k-char budget, omissions labeled), so the user's instructions never survive only as summary paraphrase; (2) an **evidence index block** — `L<line>` pointers into the session JSONL for the covered span's high-value tool output (errors from any tool first, then successful read/edit/write/bash grouped by (tool, full whitespace-collapsed command), config/schema/test targets first, per group newest + oldest, the rest by recency, 8k-char budget; each row `L<n> tool target [ERR] :: head380…tail100`), fetchable with `session_recall(line=L<n>)`. The blocks are regenerated per compaction and consumed by the keep window only while inside it (self-cleaning); a native compact (no stashed checkpoint) delivers none. The build is fail-open — any error (missing/unreadable session file, no covered range) degrades to protected-only or no blocks, never blocking the compaction.
- **`compactKeepRecentTokens` setting** — the keep window gallop's self-compaction keeps is now an extension-owned setting in the `gallop` namespace of settings-ext.json (default **8000**; loaded on `session_start`, invalid values keep the previous). The 8k default is the design point: the model-written checkpoint plus the post-compaction evidence package carry what a 20k verbatim tail would, so self-compact runs a tighter tail. It is self-compact-only — the cut override is only reachable with a stashed checkpoint, and native compacts (`/compact`, the auto threshold without a stash, overflow recovery) keep pi's own `compaction.keepRecentTokens` (default 20k) untouched. The minimum-context guard and the checkpoint guidance ("the most recent ~Nk tokens are kept verbatim") read the extension value, and the cut point is recomputed with the same `findCutPoint` walker pi's `prepareCompaction` uses whenever it differs from pi's configured window (or nuke) — pi honors the custom `firstKeptEntryId` verbatim; equal windows → pi's cut as-is; no branch entries in the event → pi's cut as-is (fail-open, the walker would otherwise throw on a missing event field). Rollback to the stock tail is one setting flip (20000) — pi's settings.json is never touched.
- **Repetitive-output collapse (bash/read tool results)** — the binary filter caught garbled-byte dumps, but the other context-killer got through: huge *text* output dominated by repeated line shapes (grep/find over a build tree — thousands of "file:line: MATCH" lines sharing the matched string; repeated error walls). Pi's 50KB truncation still injects ~12k tokens of near-duplicates, and in the field that has wrecked sessions outright (the model stops responding — 2026-06-25, 2026-09-04). A new `collapse.ts` layer in the `tool_result` path (independent toggle `repetitionCollapse`, `/gallop-collapse`) fires only on the disaster band (≥ 80 lines AND ≥ 30KB) and only on two conservative shapes: (A) the top literal lines cover ≥ 50% of all lines (identical content carries no per-line info — count-1 lines never join the group), or (B) shingle-span detection: 16-char shingles (stride 8) over an evenly-spaced 50-line sample, where two candidates co-occur ≥ 16 chars apart in one line — a LONG common region (≥ ~32 chars), i.e. most of the line is boilerplate. Shape (B) is what keeps `ls -l` / log lines with a short shared timestamp prefix and unique payload intact, and short-match grep output ("file:line: TODO" — the file:line IS the information) intact; the 30KB gate keeps smaller templated output (a few hundred npm WARNs, a long ls -l) readable. On a hit the result is replaced with head/tail examples + a count + the re-run hint; pi's truncation footer (full-output temp path) is preserved verbatim so the model can still drill in. A final shrink guard (collapsed ≥ 50% of original size → pass through) bounds the distortion. Binary suppression keeps precedence and its own toggle; the two layers no longer share a gate.
- **Nudge thresholds as exposed settings** — the context-pressure nudge's two thresholds were hardcoded (a 2k warning margin above pi's automatic threshold, a fixed 16384 (pi's default reserve) when auto-compact is off); they are now `compactNudgeBuffer` (tokens, default 2048) and `compactNudgeDisabledAt` (tokens, default 16384) in the `gallop` namespace of settings-ext.json, loaded on `session_start` like the binary toggles (materialized into the file on first load so both are visible and editable; a changed value takes effect on the next /reload or new session). Invalid file values (non-number / non-finite) keep the previous threshold; negatives clamp to 0 (a negative buffer would put the nudge at or behind the backstop). `nudgeThreshold` — and everything built on it (the nudge itself, `context_status`'s threshold line and advice tiers) — now reads the settings-loaded module state. The enabled branch stays proportional to a custom `reserveTokens`; the disabled branch has no backstop to anchor a buffer to and keeps its absolute threshold. `GALLOP_DEFAULTS` moved from binary.ts to the composition root (the namespace owner).
- **`context_status` tool** — the model had no passive view of context usage (the pressure nudge only fires near the limit), so it could not make proactive compact decisions at task boundaries or before image-heavy batches (each image ~1.6k tokens — 10 pages is a quarter of a 64k window). A new parameterless tool reports, on demand: usage vs window (percent), remaining tokens, the two backstop thresholds (gallop nudge `reserveTokens + 2k` / fixed 16384 (pi's default reserve) when auto-compact is off; pi auto-compact `reserveTokens`), and one deterministic advice line tiered by remaining distance to the nudge threshold (headroom OK / pressure building / near the backstop). It reads pi's own `getContextUsage()` — the same last-usage-anchored estimate pi's automatic threshold check uses, so the numbers match the backstop; the post-compaction `tokens: null` window reports "just compacted — safe to proceed". The description scopes the calls (task boundaries, large read/image batches — not after every tool call) so the on-demand query stays on-demand, and `compact_request`'s "Call when" list now includes `context_status` reporting pressure. Renderers follow the native pattern: bold title line, collapsed result = usage line, full text on expand.
- **Task-boundary compaction hint** — `compact_request`'s "Call when" guidance now includes a proactive trigger for multi-task sessions: when a planned task finished and another is queued, write the checkpoint now (with `continue: true`) so the next task starts on a fresh context. The pattern proved in the field: a three-task session compacted at every boundary — the checkpoint summary plus the verbatim tail is a complete handoff, and the KV cache is rebuilt by compaction anyway, so a boundary compact costs nothing relative to running hot until the pressure nudge fires.
- **`compact_request` minimum-context guard** — with the context at or below pi's keep window (`compaction.keepRecentTokens`, default 20k) there is nothing older than the verbatim tail to summarize, and pi fails the compact (field: a ~11k-token session compacted via the tool died in pi as "session too small"). The tool now checks pi's own `getContextUsage()` (the same last-usage-anchored estimate the automatic threshold check uses) against the live settings *before* stashing: at or below the minimum the call fails as the tool call itself — the error thrown from `execute` becomes the tool result, telling the model the reason and to retry once context grows — and nothing is stashed, so the deferred compact never fires. Unmeasurable usage (`tokens: null` in the window right after a compaction) proceeds and lets pi decide. The tool description names the failure condition, so the model doesn't spend a full checkpoint write on a doomed call.
- **`compact_request` `nuke` flag** — when the context is broken beyond repair (repeated failing tool calls), pi's default ~20k verbatim tail keeps exactly the broken part. The model can now pass `nuke: true` to summarize the *entire* context, keeping only the last turn's tail. `execute` stashes the flag; `session_before_compact` recomputes pi's cut point with budget 0 — the same exported `findCutPoint` walker pi's `prepareCompaction` uses, mirroring its previous-compaction boundary logic — and returns the custom `firstKeptEntryId`, which pi uses verbatim (verified against pi's internals: `prepareCompaction` is not overridable from a hook, but a custom cut id is honored as-is; a soft in-context nuke is impossible because pi bails on sessions at or below the configured keep window *before* the hook runs). The minimum-context guard now fails a nuke on a too-small session with an explicit escape hatch: pi evaluates the cut with the *configured* window — never 0 — and refuses the compact at all, so the model is told to persist the state to memory (or a handoff file) and have the user start a new session. The description splits trigger (bullet: when + full-state obligation) from mechanics (param: what the flag does) with no duplication, and the nuke checkpoint must carry full state, not just older work.

### Changed
- **Completion marker wording** — "[Gallop] Compaction complete — the summary at the top of context is your current state. Do not call compact_request again unless context pressure returns." → "[Gallop] Compacted — proceed. The summary at the top of context is your current state; do not call compact_request again."
- **Evidence index degrades to fragments when `session_recall` is unavailable** — the evidence header unconditionally instructed the model to fetch full payloads via `session_recall`, but that tool is owned by the memory extension and gallop had no way to know whether it was loaded (the extension API exposes no tool introspection) — with memory absent, every row pointed at a tool the model could not call. The model's tool set is now tracked from the `tools` array of the last provider request (`before_provider_request`; both the Anthropic `tools[].name` and OpenAI-compatible `tools[].function.name` shapes; tools-less requests — e.g. the one-shot summarizer's plain completion — never overwrite the last known set). When `session_recall` is not among the model's tools, the evidence block renders fragments only: no `L<n>` prefixes, no fetch instruction, a fragment-worded header — built from the in-memory entries with no session-file read (the head…tail fragments still carry the exact values; the protected block is unaffected). No tools-carrying request observed in the process yet → fail-open to the pointer behavior (unreachable in practice — a self-compact requires a model turn); a new session clears the tracked set.
- **`compact_request` keep window moves from pi's settings to the extension's** — the nuke's budget-0 cut override and the new keep-window override now share one path in `session_before_compact`: budget = `nuke ? 0 : compactKeepRecentTokens`, recomputed with pi's `findCutPoint` walker and returned as a custom `firstKeptEntryId` (pi's cut stays the fallback when no usable custom cut exists or the event carries no branch entries). The override is only reachable with a stashed checkpoint, so native compacts keep pi's cut as-is. The minimum-context guard and `checkpointFormat` no longer read pi's `compaction.keepRecentTokens` — they read the extension setting (live module state for the guard, load-time value for the registration-time guidance; `context_status` still reports pi's own thresholds, since it reports pi's backstop).
- **Window-scaled nudge threshold (`compactNudgePct`, default 0.25)** — the nudge threshold was a fixed token count on both branches (~18k with auto-compact on, 16384 off), which is a late nudge on large windows: one big tool result or a batched read turn can burn 16k+ tokens, so on a 114k+ window the context ran out before the model reached a pause point to compact (field: overflow aborts when auto-compact is off). The effective threshold is now `max(configured base, pct × contextWindow)` on both branches — 16384 is exactly 25% of a 64k window, so small windows stay on the configured base (zero behavior change) while the margin scales up on large ones (200k window → ~50k, 114k → ~28.7k). New `compactNudgePct` setting (fraction 0–1, default 0.25; 0 = fixed base only) joins `compactNudgeBuffer` / `compactNudgeDisabledAt` in the `gallop` namespace (loaded on `session_start`; out-of-range values clamp to [0, 1], invalid values keep the previous). `context_status`'s threshold line and advice tiers — including the 2× "pressure building" band — track the scaled threshold automatically. The nudge steer now says "running low" instead of "nearly full" (at a 25% floor the context is not near full on large windows). The window-less path (no model / unknown window) keeps the fixed base.
- **`compact_request` drops the `message` parameter** — it only shaped the transient `Compacting (…)` result line, which the context handler replaces with the completion marker as soon as the compaction runs: after compaction — the only moment the model sees its own call again — the parameter had zero effect, and before compaction it was user-visible in the TUI only. The fixed `Compacting.` result carries that role now, saving the per-call LLM decision and two lines of description.
- **`compact_request` `continue` now defaults to on** — an omitted `continue` used to mean "stop after compaction", so a forgotten argument stranded a live task at the compaction boundary. The failure costs are asymmetric: a mistaken *continue* costs at most one idle "nothing to do" turn, while a mistaken *stop* abandons in-flight work. Omitted now means continue (the generic proceed steer fires); pass `false` explicitly to stop. Tool description and schema updated; the self-compact suite pins both the default and the explicit stop.
- **Checkpoint format names the actual kept-tail size** — pi's `compaction.keepRecentTokens` (default 20k) is user-configurable, but the checkpoint guidance hardcoded "~20k tokens are kept verbatim", which misinforms the model when it differs (over- or under-summarizing). `readPiCompactionSettings` now reads `keepRecentTokens` too, and the tool description names the configured value (read at registration — a changed value takes effect on the next /reload, like the rest of the extension's load-time state). `checkpointFormat()` is exported for tests.

### Renamed
- **`request_compact` → `compact_request`** — unified the extension's tool naming to `object_action` (session-wide convention; `context_status` already fit). Name, prompt strings, renderers, README, and tests updated. No legacy-name detection: sessions that already called `request_compact` simply keep those calls in their history (the context handler no longer matches them).

## v2.1.0 — 2026-08-19

### Fixed
- **Double compact at the automatic threshold ("Compaction failed: Already compacted")** — when a run's final usage crossed pi's automatic threshold (default 16k remaining), the `request_compact` compact — fired inside the tool's `execute` — always lost the race: `ctx.compact()` first awaits the agent to go idle, which only happens AFTER pi's post-run loop where the automatic compact runs. The automatic compact consumed the stashed checkpoint first, then the manual compact threw "Already compacted" and the TUI showed an error. The compact is now deferred: the tool stashes the summary, marks the request pending, and returns `terminate: true`; the actual `ctx.compact()` fires on `agent_settled` (emitted after the post-run loop). If the automatic compact ran first, `session_compact` clears the pending state and the deferred trigger is a no-op (a second check that the branch does not already end in a compaction entry). In the race case the `continue` steer is sent from `session_compact` instead of the (never-run) manual `onComplete`. `message_end` now triggers nothing (pi emits it *before* pending tool calls execute), so the v2.0.1 pending-call special case is gone with it.

### Added
- **Context-pressure nudge** — as the context nears its limit, gallop steers the live model to self-compact: one advisory steer per compaction cycle, placed just above pi's automatic threshold — `reserveTokens + 2k` (default ~18k remaining) when auto-compact is on, or a fixed 16k when it is off (no backstop exists then, and an overflow would abort the run). The threshold reads pi's compaction settings from the global + project `settings.json` (merged per key, project wins — same read-only reader shape as the context extension, falling back to pi's defaults), so it tracks a custom `reserveTokens` and stays proportionate on small (e.g. 64k) context windows. After the nudge, silence — pi's automatic compaction (which also drives overflow recovery, so it stays enabled as the backstop) decides. No nudge while a compact is pending or in flight, when a message ends in aborted/error, or when the circuit breaker has halted the agent.

### Removed
- **`/qcompact`** — superseded by the context-pressure nudge (the model is asked to compact itself as the context fills) and pi's native `/compact` (immediate, cold one-shot). With it goes the non-compliance fallback path and its `qcompactSteering` state.

### Tests
- Rewrote the self-compact suite for the deferred semantics (stashes + defers to `agent_settled`, re-entrancy guard, `message_end` with a pending `request_compact` triggers nothing, state reset on `session_compact`, branch-ending check, and the 16k race regression — automatic compact consumes the stashed summary → deferred trigger is a no-op, continue steer sent from `session_compact`). New `context-pressure nudge` suite (threshold math from settings — per-key merge, project override, disabled → 16k, missing/malformed fallback; one nudge on the enabled and disabled paths, reset after compaction, skip conditions) and `contextTokensFromUsage` units. 118 tests total.

## v2.0.1 — 2026-08-17

### Fixed
- **`/qcompact` native fallback fired before the model's `request_compact` call executed** — pi emits `message_end` *before* pending tool calls run, so the "model did not comply" fallback saw the steering still armed, started an un-stashed native compact, and pi's `compact()` (which aborts the run first) killed the pending `request_compact` tool call — the tool result became `Operation aborted`, its trigger was blocked by the re-entrancy guard, and the compaction entry was a stale native one-shot rewrite instead of the model's checkpoint. The fallback now skips `message_end`s that carry a pending `request_compact` tool call (keeping the steering armed for the next `message_end`); any other pending tool call or text end still falls back immediately.

### Tests
- Added 2 regression tests: pending `request_compact` defers the fallback (the subsequent tool execution triggers the in-session compact with the stashed summary), and a non-`request_compact` pending call still triggers the native fallback.

## v2.0.0 — 2026-08-17

### Changed
- **Self-compact: the model writes the checkpoint summary in-session** — `request_compact` now requires a `summary` argument written by the live model (pi's checkpoint format, focused on older work since the recent ~20k tokens are kept verbatim). Summarization happens inside the session as a normal turn, so that LLM call rides the session's cached prompt prefix (cache-warm) — no subprocess, no cold prefill of the flattened conversation. Gallop stashes the summary and returns it as a custom `CompactionResult` in `session_before_compact` (with pi's file-list sections appended), so pi skips its one-shot summarizer.
- **`reason`/`pending` replaced by `message`/`continue`** — `message` is a short user-visible string carried by the tool result (`Compacting (<message>).`); the summary is no longer echoed in the result. `continue` (boolean) replaces the free-text resume task: when `true`, one fixed generic steer is injected after compaction (`[Gallop] Compact done — proceed as commanded.`) — the checkpoint's Next Steps section carries the actual "what next", so no custom resume text is ever written or re-sent (the old `pending` text appeared up to three times in context).
- **`/qcompact` restored** — steers the live model to write the checkpoint and call `request_compact` (same cache-warm path, optional focus argument); if the model does not call the tool by `message_end`, gallop falls back to `ctx.compact()` (pi's native one-shot), so `/qcompact` always compacts.
- **Fallback chain** — native `/compact`, auto threshold, overflow recovery, a summary under 200 chars, or a user abort all return `undefined` from `session_before_compact`, so pi's native one-shot runs and compaction always works.

### Fixed
- **"Already compacted" re-entrancy** — `ctx.compact()` internally aborts the run executing `request_compact`, which can re-trigger a compaction while the last session entry is still the compaction entry (pi then throws "Already compacted"). A `compactionInFlight` guard skips redundant triggers; it is re-armed only at true new-turn boundaries (new user message, `/qcompact`, new session) — not on `session_compact` or compact complete/error, so the guard stays active through the whole re-trigger window.

### Notes
- **`request_compact` summary-arg pruning** — the checkpoint text also exists as the tool call's `summary` argument in the kept tail (~1k duplicated tokens on every request). A `context` handler prunes that argument from each LLM request once the exact text is verifiably carried by the compaction summary (byte-identical prefix match — gallop appends the file sections after the text, never before). Pre-compact tree views (no `compactionSummary` message), earlier compactions' tool calls, and newer aborted calls fail the check and keep their full argument. The session file is never touched (the TUI transcript still shows the full summary); the rewrite is deterministic, so the prefix stays cache-stable. Out-of-band forking would remove the tail copy by construction but costs a subprocess and byte-identical-prompt fragility (any drift in the serialized tools array cold-prefills the whole fork request, as observed live); the in-session design was kept deliberately.
- The `[Gallop] Resume: <task>` injection is gone (no more free-text resume task); the fixed `[Gallop] Compact done — proceed as commanded.` steer is distinct from stall-detection resume messages.

### Tests
- Rewrote `self-compact.test.ts` (110 tests passing total): file-list helpers, tool behavior (stashing, terminate result, message defaulting, no summary echo, `continue` on/off), `session_before_compact` (custom compaction with file ops, native fallback for missing/short summaries, abort-listener register/cleanup, no stale-summary reuse), re-entrancy guard, `/qcompact` (steering content, focus, non-compliance fallback, no double-compact on compliance, refusal while running), state reset on `session_compact`, and the `context` summary-arg pruning handler (prune on verbatim carry, no-op without a compaction summary, non-matching/too-short args intact, multi-call selection, non-array content tolerated).

## v1.6.0 — 2026-08-01

### Fixed
- **Sticky repetitive-call blocks** — a blocked fingerprint stayed hard-blocked for the whole session (until compaction/restart), so a legitimate later re-use of the same call (e.g. `npm run build` after editing files) was blocked on first occurrence with a misleading message. A successful call now clears the repetitive escalation state, mirroring the failure-loop success clearing.
- **Settings clobber risk** — Gallop wrote pi's own `~/.pi/agent/settings.json` with an unlocked read-modify-write, racing pi's locked writes (proper-lockfile) and risking lost keys or corrupted JSON. Toggles now live in `~/.pi/agent/gallop.json`; legacy values in settings.json are migrated on first load.
- **Read guard false positives on ASCII CAD formats** — `.stl`, `.obj`, `.step`, `.iges`, `.dxf` are often plain text and are no longer blocked; binary variants (binary STL etc.) are caught by the result sniff. `.dwg` and `.3mf` remain blocked.
- **Binary sniff missed U+FFFD walls** — the read tool decodes bytes via `buffer.toString("utf-8")`, so null-free binaries become walls of U+FFFD replacement chars with no control characters left to flag. `detectBinaryContent` now flags >5% replacement characters, and suppressed summaries strip them from the preview.
- **No-UI circuit breaker message said "0 blocks enforced"** — the count is now captured before the state reset.
- **Blocked calls polluted failure-loop history** — blocked calls still emit `tool_execution_end` with the block reason as the error result; those are no longer recorded as failures or fed to mismatch detection (fingerprints starting with `[gallop]` are skipped).
- **Stall escalation didn't match README** — normal `toolUse` handoffs now reset the consecutive-stall streak, and stalls within the 10s message cooldown still count toward escalation, so fast stuck loops escalate to stop instead of resuming forever.
- **Stale pending task after cancelled compaction** — `pendingTask` is cleared when compaction is aborted or errors, so a later unrelated compaction no longer shows "(will resume)" for an old task.

### Changed
- Dead block thresholds (7) replaced with the effective 5.

## v1.4.0 — 2026-07-21

### Fixed
- **False-positive repetitive-call blocks for nested args** — the default fingerprint branch used `JSON.stringify(a, Object.keys(a).sort())`, and an array replacer drops keys at *every* depth, so `{query:"q", options:{limit:5}}` and `{query:"q", options:{limit:99}}` fingerprinted identically. - **Potential `pendingToolCalls` leak** — `tool_execution_start` stashes before `tool_call` runs; if `tool_execution_end` never fires for a blocked call, the entry would leak. Map is now capped at 200 entries (oldest dropped).
- **README** — hex head preview documented as 16 bytes; code dumps 64.

## v1.3.0 — 2026-07-03

### Fixed
- **Stall detection for tool-call stops** — `lastItemIsToolUse` checked `type === "tool_use"` but assistant content blocks use `type === "toolCall"`, so it always returned false and "stopped after tool call" stalls were never detected. Now checks `"toolCall"`.
- **Spurious resume on normal tool handoffs** — `stopReason` was compared to `"tool_use"` (snake_case) but the value is `"toolUse"` (camelCase). After the fix above this would have injected a resume message on every normal tool call; now correctly skips normal `toolUse` stops.
- **Reasoning-action mismatch never fired** — two independent bugs: (1) `tool_execution_end` read `event.args`, which doesn't exist on that event, so the failed-call fingerprint was always `toolName:{}`; (2) the mismatch check looked for `type === "tool_use"` / `input` instead of `type === "toolCall"` / `arguments`. Args are now stashed in `tool_execution_start` and looked up by `toolCallId`, and the content-block shape is correct. The check also iterates all tool calls (parallel-safe) and runs before the stall early-return so it actually reaches normal tool handoffs.
- **Repetitive-call block could miss on coerced args** — the block was recorded with a fingerprint from `tool_execution_start` (raw args) but looked up with one from `tool_call` (validated/coerced args). Now looks up the stashed fingerprint first.
- **False repetitive-success nudge after bash failures** — a bash failure left the consecutive-call counter incremented, so a later successful run of the same command could trigger a repetitive-call nudge. The counter now resets on bash failure.

### Changed
- **Removed context usage injection** — the `before_agent_start` context-usage message (`Context: 42.3k / 128k (33%)`) added noise without helping in practice. Removed the handler, the `lastReportedPct` state, and the `formatTokens` helper.

### Performance
- **Binary filter** — encodes the bash output to bytes once instead of twice when building the suppression summary.
